# Plan: Clean GitHub-only SMC Toolkit Website

## Goal

Create a clean static HTML version of the existing SMC Toolkit for the `smclogic.github.io` repository. Preserve the current visual design, navigation, chart behavior, indicators, calculations, and user interactions, while removing Google Apps Script dependencies and using only repository-hosted JSON/CSV data generated by a free GitHub Actions plus Python workflow.

## Scope and key decisions

The new website will be a static GitHub Pages-compatible site. The browser will load data with relative paths such as `./data/nepse_ohlc.json` and `./data/nepse_ohlc_fast.json`, so the code will not contain username/repository placeholders or external Apps Script URLs. The repository will act as the database: JSON will be used by the browser for fast loading, and CSV will be retained for inspection, download, and backup.

The existing HTML will be audited for every `script.google.com`, Google Sheets, Apps Script, and other external data call. Each required data field will be mapped to a repository file. The SMC Chart’s existing wide-row contract will be preserved, including `Date`, index/sub-index OHLC and turnover columns, and symbol OHLC and volume columns. Existing chart parsing, timeframe conversion, indicators, SMC calculations, selectors, replay mode, overlays, and layout will remain unchanged unless a source reference must be renamed.

The Python updater will use free public data sources already verified for this project: ShareSansar’s market page for index and sub-index OHLC/turnover, and ShareSansar’s today-share-price page for listed-company daily OHLC/volume. It will validate the trading date, require a minimum number of valid symbol rows, replace duplicate same-date rows safely, and write the full history, latest snapshot, compact fast file, per-date archive, CSV, and manifest.

The existing daily GitHub Actions workflow will remain deterministic and free of paid NEPSE API calls. It will run manually and on the Sunday–Thursday Nepal trading schedule, install the small Python dependency set, run the updater and tests, and commit only changed `data/` files. It will not deploy or overwrite unrelated website files.

## Implementation phases

### 1. Inventory and dependency audit

Inspect the uploaded HTML and identify all application sections, data loaders, external URLs, Apps Script references, Google Sheets references, and fields consumed by each application. Separate pure client-side logic from data-dependent logic. Confirm whether the repository’s current homepage is an unrelated website before choosing whether the clean output should be named `index.html` or remain a separate file until the user confirms replacement.

### 2. Define the GitHub data contract

Create a small, documented repository data model. The primary files will be `data/nepse_ohlc.json`, `data/nepse_ohlc_fast.json`, `data/latest.json`, `data/nepse_ohlc.csv`, `data/latest.csv`, `data/history/YYYY-MM-DD.json`, and `data/manifest.json`. If the audit finds additional fields required by other tabs, add separate repository JSON files with explicit schemas rather than embedding hidden external calls in the HTML.

### 3. Build the clean Python data updater

Keep the saved Python scraper in `scripts/update_nepse.py`, improve normalization and validation where the audit requires it, and preserve the current SMC Chart wide-row format. Add tests for source parsing, missing/partial data rejection, date deduplication, stable sorting, generated JSON validity, and CSV headers. Do not use simulated market data.

### 4. Build and verify the GitHub Actions workflow

Place the workflow at exactly `.github/workflows/daily-nepse.yml`. Support `workflow_dispatch` for manual verification and a Nepal-time post-market cron for Sunday through Thursday. Set repository content write permission, install from `requirements.txt`, run the updater with a minimum symbol threshold, and commit only `data/` changes. Keep the job safe on repeated runs and avoid committing Python cache files.

### 5. Produce the clean HTML output

Create a clean copy of the uploaded HTML, preserving the current UI and application logic. Remove Apps Script and Google Sheets URLs from the SMC Chart and replace them with relative repository paths. Remove obsolete Apps Script-specific error messages, configuration labels, and fallback assumptions. Where other tabs require data not supplied by the free NEPSE dataset, either migrate their data to a documented repository file or clearly mark the dependency as unresolved rather than silently breaking the tab.

The clean site will preferably use `index.html` at the repository root only after confirming that doing so will not destroy the user’s unrelated existing homepage. Otherwise, deliver `smc_toolkit_clean.html` first and provide the exact safe rename/backup step.

### 6. Test and package

Run the Python unit tests, JSON syntax checks, CSV consistency checks, HTML source checks for zero Apps Script references, relative data URL checks, and a local static-server smoke test. Confirm that the latest real scrape contains valid index OHLC and a complete symbol set. Package the clean HTML, scripts, workflow, data files, tests, and README for upload to `smclogic.github.io`.

## Acceptance criteria

| Area | Acceptance condition |
| --- | --- |
| UI | The clean HTML preserves the current SMC Toolkit layout, navigation, responsive behavior, themes, chart controls, indicators, overlays, and calculations. |
| External dependencies | No `script.google.com`, Google Sheets, Apps Script endpoint, or paid NEPSE API remains in the clean SMC site. CDN libraries already required by the existing UI may remain unless they are also requested to be self-hosted. |
| Data | The chart loads from repository JSON using relative paths and recognizes index, sub-index, and symbol OHLC data in the existing format. |
| Automation | GitHub Actions can be run manually and can update the data files on the scheduled Nepal trading-day cadence. |
| Safety | Partial or malformed source responses fail the workflow without overwriting the last valid dataset. |
| Repository | Only `data/` is modified by the scheduled commit; existing unrelated site files are not deleted automatically. |
| Verification | Unit tests, generated JSON/CSV validation, source-reference audit, and local static loading checks pass. |

## Assumptions and open risks

The main assumption is that the user wants the SMC Toolkit’s visible UI and client-side logic preserved, but wants its data layer moved to GitHub. The free public source pages are not a guaranteed licensed API; their HTML structure or access behavior can change, so the parser may need maintenance. GitHub scheduled workflows can start late, so manual dispatch remains available.

The uploaded Apps Script currently exposes a much broader historical wide-row dataset than the fresh public daily scrape. The new pipeline will not depend on that endpoint at runtime. If the user wants the entire old historical range retained, it must be exported once as a controlled seed and reviewed before committing it to the public repository.

The existing repository may contain another homepage. The clean implementation will avoid destructive replacement unless the user confirms that the SMC Toolkit should become the repository’s main `index.html`.
